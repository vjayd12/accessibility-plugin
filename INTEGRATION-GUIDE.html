Integration Guide — v2.0.0 (plain HTML / CMS)

What's in the Package

FilePurpose

Zero dependencies. A single JavaScript file with all icons embedded inline. It loads no external images, fonts, stylesheets or libraries and makes no network requests.

Quick Start

  1. Copy the script into your project

    Place dwao-a11y-widget.js in your site's scripts folder, for example:

    your-website/
  js/
    dwao-a11y-widget.js
  index.html

  2. Add the button container

    Add this markup inside <body>. Leave the button empty — the widget fills in the icon and the "Accessibility" label.

    <div class="accessibility-div">
  <button id="accessibilityToggleBtn"></button>
</div>

  3. Add the script tag

    Place it after the button container, just before </body>:

    <script src="js/dwao-a11y-widget.js" data-position="bottom-left"></script>

    That's it. The widget initialises as soon as the script runs. Click the button to open the panel.

Configuration Options

Configure the widget with data-* attributes on its script tag. All are optional.

<script
  src="js/dwao-a11y-widget.js"
  data-position="bottom-right"
  data-theme="blue"
></script>
AttributeValuesDefaultDescription
data-positionbottom-left, bottom-right, top-left, top-rightbottom-leftWhere the button and panel appear
data-themedefault (#007abc), purple (#663db3), blue (#0073BB), green (#00875A)defaultAccent colour of the button and panel
data-brand-colorHex colour: #rgb, #rrggbb or #rrggbbaa—Overrides data-theme. Any value that is not a hex colour is ignored and the theme colour is used.
data-page-langBCP 47 code, e.g. en, en-IN, hi—Language of your page content. Used only if <html> has no lang attribute.
data-langenenReserved. The panel is English-only in v2.0.0 and this attribute currently has no effect.

What the Widget Changes on Your Page

As soon as it loads, v2.0.0 repairs some common accessibility problems on the host page. It checks content added later (modals, AJAX, route changes) as well.

Automatic fixWhat it does
Field labelsCopies the name attribute into aria-label only on inputs, selects and textareas that have no accessible name at all (no <label>, aria-label, aria-labelledby, title or placeholder). Fields you have labelled are never changed. This is a last resort; give every field a visible <label>.
Iframe titlesGives untitled iframes a title such as "Embedded content from example.com"
Password pasteRemoves onpaste="return false" from password fields so password managers work. The value is never read.
Skip linkInserts a "Skip to main content" link pointing at <main> (or the first <h1>) unless the page already has one
Page languageIf <html lang> is missing, sets it from data-page-lang, or as a last resort guesses from the visitor's browser language and logs a console warning. Set lang on <html> yourself.
ZoomRemoves user-scalable=no and raises maximum-scale to at least 2 in the viewport meta tag

Tip: these fixes are a safety net, not a substitute for fixing the source markup. Wrapping your main content in <main> gives the skip link the best target.

CMS-Specific Instructions

WordPress

Upload dwao-a11y-widget.js to your theme's js/ folder and add this to footer.php, before </body> (or use a plugin such as "Insert Headers and Footers"):

<div class="accessibility-div">
  <button id="accessibilityToggleBtn"></button>
</div>
<script src="<?php echo get_template_directory_uri(); ?>/js/dwao-a11y-widget.js"
        data-position="bottom-left"></script>

Shopify

Upload the file to your theme's Assets, then add this to theme.liquid before </body>:

<div class="accessibility-div">
  <button id="accessibilityToggleBtn"></button>
</div>
<script src="{{ 'dwao-a11y-widget.js' | asset_url }}" data-position="bottom-left"></script>

Adobe Experience Manager (AEM)

Add the script to a clientlib loaded at the end of the page body, and place the button container in your page template or footer component. Keep data-* attributes on the script tag that loads the file.

React, Angular and other single-page apps

Use the dedicated React or Angular kit instead of this file. Their build of the widget adds DWAOAccessibility.reinit() for client-side route changes. This build has no reinit(), and loading it a second time (for example from a component that mounts twice) creates a second panel.

Styling the Button

The widget positions the button itself (see data-position) and colours it with the theme or brand colour. To change the colour, use data-theme or data-brand-color rather than CSS. For other tweaks, target #accessibilityToggleBtn and .accessibility-panel. Positioning rules use !important, so avoid overriding position.

Content Security Policy (CSP)

The widget injects its own <style> elements and inline styles, so a strict CSP must allow inline styles. It needs nothing else beyond loading the script itself:

script-src 'self';
style-src  'self' 'unsafe-inline';

No font-src, img-src or connect-src entries are needed.

Data & Privacy

The only data stored is the visitor's own list of selected options, kept in localStorage under the key accessibility_local_settings. The widget sets no cookies, sends no network requests, and never reads, stores or displays the contents of password fields.

JavaScript API

The widget exposes window.DWAOAccessibility:

window.DWAOAccessibility.version;   // "2.0.0"
window.DWAOAccessibility.reset();   // turn off every accessibility setting

Troubleshooting

  1. No button appears: the page must contain <div class="accessibility-div"> with <button id="accessibilityToggleBtn"> inside it, and that id must be unique.
  2. Script not loading: check that the src path points to dwao-a11y-widget.js (look for a 404 in the browser's Network tab).
  3. Button does nothing: the script must come after the button container, so the button exists when the widget starts.
  4. Options ignored: data-* attributes must be on the widget's own script tag. An invalid data-brand-color falls back to the theme colour.
  5. Panel unstyled: your CSP is blocking inline styles; see the CSP section above.
  6. Site CSS clashes with the panel: the panel's root element is .accessibility-panel; raise the specificity of your own rules if they leak into it.
