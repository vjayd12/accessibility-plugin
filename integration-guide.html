DWAO Accessibility Widget

React Integration Guide  |  v2.0.0  |  Enterprise Standard

A self-contained, zero-dependency JavaScript widget (acc.js) that adds a WCAG-compliant accessibility panel to any React application — text size, contrast, dyslexia font, reading line, cursor size, and more.

No npm packages No build-step changes localStorage only — no server calls React 17+  /  TypeScript 4.5+

Integration Steps

Step 1Host the Widget Script

Place acc.js inside the public/ directory of your project. Both Vite and CRA serve everything in public/ as static assets at the root path (/acc.js).

your-project/
  public/
    acc.js    ← add here
Do not import acc.js via src/ — it must remain a plain <script> tag, not a module bundled by Vite or Webpack.

Step 2Configure Environment Variables

Add widget configuration to your .env file so settings can vary across environments (dev / staging / prod).

# .env
VITE_A11Y_WIDGET_POSITION=bottom-left
VITE_A11Y_WIDGET_THEME=purple
VITE_A11Y_BRAND_COLOR=
For Create React App, prefix variables with REACT_APP_ instead of VITE_.

Step 3Update index.html

Add the toggle button markup and script tag to your root index.html. Vite supports %ENV_VAR% interpolation directly in index.html, so environment variables are injected at build time. 

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1.0" />
  <title>Your App</title>
</head>
<body>
  <div id="root"></div>

  <!-- DWAO Accessibility Widget -->
  <div class="accessibility-div">
    <button id="accessibilityToggleBtn"></button>
  </div>
  <script
    src="/acc.js"
    data-position="%VITE_A11Y_WIDGET_POSITION%"
    data-theme="%VITE_A11Y_WIDGET_THEME%"
    data-brand-color="%VITE_A11Y_BRAND_COLOR%"
  ></script>

</body>
</html>
Do not put any text inside #accessibilityToggleBtn — the widget auto-populates the icon and label.

Available data-* attributes:

AttributeValuesDefaultDescription
data-position bottom-left, bottom-right, top-left, top-right bottom-left Toggle button position on screen
data-theme purple, blue, green purple Widget color theme
data-brand-color Any hex e.g. #0073BB — Overrides theme with a custom brand color
data-lang en en Widget UI language

Step 4Add TypeScript Global Type Declaration

Create src/types/dwao.d.ts to prevent TypeScript errors when accessing window.DWAOAccessibility:

// src/types/dwao.d.ts
export {};

declare global {
  interface Window {
    DWAOAccessibility?: {
      reinit: () => void;
    };
  }
}

Ensure src/types/ is covered by your tsconfig.json:

{
  "include": ["src"]
}

Step 5Create the Reinit Hook

React Router replaces DOM content on every navigation without a full page reload. The widget must re-scan the DOM after each route change to function correctly on new pages.

Create src/hooks/useAccessibilityReinit.ts:

// src/hooks/useAccessibilityReinit.ts
import { useEffect } from 'react';
import { useLocation } from 'react-router-dom';

export function useAccessibilityReinit(): void {
  const location = useLocation();

  useEffect(() => {
    const idleCallbackId = requestIdleCallback(() => {
      window.DWAOAccessibility?.reinit();
    });

    return () => cancelIdleCallback(idleCallbackId);
  }, [location.pathname]);
}

Step 6Register the Hook in App.tsx

Call the hook once at the root of your app, inside <BrowserRouter>. A separate inner component is required because useLocation() needs Router context. 

// src/App.tsx
import { BrowserRouter, Routes, Route } from 'react-router-dom';
import { useAccessibilityReinit } from './hooks/useAccessibilityReinit';

function AppInner() {
  useAccessibilityReinit();

  return (
    <Routes>
      <Route path="/" element={<Home />} />
      <Route path="/dashboard" element={<Dashboard />} />
      {/* ...other routes */}
    </Routes>
  );
}

export default function App() {
  return (
    <BrowserRouter>
      <AppInner />
    </BrowserRouter>
  );
}

Testing Considerations

Mock window.DWAOAccessibility in your test setup to prevent errors in unit and integration tests:

// src/setupTests.ts
window.DWAOAccessibility = {
  reinit: jest.fn(),
};

Content Security Policy (CSP)

If your application enforces a Content-Security-Policy header, ensure the widget script source is whitelisted: 

script-src 'self' https://your-cdn.com;
If acc.js is served from public/ (same origin as your app), 'self' is sufficient and no CSP changes are needed.

Notes

The widget uses z-index: 9999. Ensure no app-level overlays (modals, drawers, toasts) use a higher z-index without accounting for the accessibility panel.
id="accessibilityToggleBtn" must be unique across the entire page — do not duplicate it.
User preferences persist in localStorage under dwao-a11y-* keys and survive page reloads automatically. No action is needed to restore state.
The widget initializes synchronously when the <script> tag is parsed — it does not need to wait for React to mount.
